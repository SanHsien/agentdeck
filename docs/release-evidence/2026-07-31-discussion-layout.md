# 實機證據：AI 圓桌版面（P5）

日期：2026-07-31 · 版本：v0.31.2+（修正 commit 見本檔結尾）

## 環境

| 項目 | 值 |
|---|---|
| Windows | 11 專業版 10.0.26200（build 26200） |
| WebView2 Runtime | 150.0.4078.105 |
| 系統顯示縮放 | 225%（`devicePixelRatio` 實測 2.25） |
| 驗證工具 | `tools/verify_discussion_layout.py`（實機開窗 + DOM 幾何量測） |

DPI 1.0 與 1.5 以 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--force-device-scale-factor=N` 模擬，
不改動系統顯示設定。

## 判定條件

清單**可以**捲動；不可接受的是「捲到最上面時第一張卡仍被切掉」。因此以
`model` / `persona` 控制項的 `belowFold`（相對捲動容器下緣的位移）為準，
負值代表完整在可視範圍內。

**不以「容器高度 ≥ 卡片高度」作為判準** —— 第一版判定就是這樣寫的，結果對一個
肉眼可見裂開的版面回報 PASS：容器上方還有區段標題，卡片並非從容器頂端開始。

## 修正前（`e94e8ef`）

900×640 @ 2.25：捲動容器可視 **117px**，`model` / `persona` `belowFold = +24`
→ 兩個下拉選單被切掉 24px。

## 修正後

`.setup` 的 `max-height` 由 `clamp(300px, 52vh, 640px)` 改為 `60vh`；
`.controls-scroll` 的 `min-height` 由 `0` 改為 `150px`（區段標題 + 一張完整卡片）。

| DPI | 尺寸 | CSS 視窗 | 捲動可視 | `belowFold` | 水平捲軸 | 結果 |
|---|---|---|---|---|---|---|
| 1.00 | 900×640 | 1997×1361 | 443px | −342 | 無 | PASS |
| 1.00 | 1280×800 | 2852×1721 | 443px | −342 | 無 | PASS |
| 1.50 | 900×640 | 1332×908 | 348px | −247 | 無 | PASS |
| 1.50 | 1280×800 | 1902×1148 | 444px | −343 | 無 | PASS |
| 2.25 | 900×640 | 888×605 | 166px | **−24** | 無 | PASS |
| 2.25 | 1280×800 | 1268×765 | 262px | −162 | 無 | PASS |

最緊的是 **225% + 900×640**，餘裕 24px。這也是唯一會落在 `max-width: 1050px`
換列斷點內的組合（DPI 1.0 時 CSS 視窗寬達 1997px，走的是單列版面）——
兩種版面都在矩陣內被驗證到。

## 重現方式

```
python tools/verify_discussion_layout.py 900x640 1280x800
```

離開碼 0 代表全數通過；失敗時會逐項印出超出幾 px。
